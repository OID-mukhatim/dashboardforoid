# Architecture rules
- Composite scoring and eligible-source completeness use the weights in the shared profile helper; excluded components retain standalone scores with zero weight so consumers remain consistent without altering source calculations.
- Alerts share one authenticated loadAlerts endpoint and pure rule helpers; dashboard snapshot reads use a server-only helper to avoid nested server-function RPC calls.
- Latest gap-period selection is shared by alert and initiative rules; initiative generation inserts missing codes with conflict-ignore to protect existing decisions.
- Organization detection uses the shared org-aliases module for uploads, document mentions, and filenames to prevent inconsistent attribution.
- Upload localization uses the shared language dictionary for interface text and the existing cached translation component for extracted content; keep persisted filter values and parser inputs unchanged so language switching cannot alter imports.
- Financial advisor work lives in the advisor_snapshots table as an append-only monthly record (one row per source upload, uncovered orgs carried forward), and the composite financial score is computed live in the dashboard snapshot from all advisor reports (recency-weighted) plus budget execution from financial_reports; this keeps history intact and scores updating automatically.
- Governance status-to-score conversion (policy records, uploaded assessment files, derived statuses) uses the single shared gov-likert module; pending and blank answers are excluded so every surface stays consistent.
- Institutions come only from the organizations table via the shared org-registry (filled in-place by OrgsGate on the client and loadOrgRegistry inside each server handler); archived rows stay in ALL_ORGS only, so lists, filters, alerts and calculations skip them while history keeps them.
- Data changes are captured by one SECURITY DEFINER audit trigger into the append-only audit_log (admin read only, no client writes); update rows that change only updated_at are skipped.
- Each section is its own route under the _authenticated/_shell pathless layout (header + sidebar + Outlet); "/" redirects to /dashboard and admin-only pages wrap their component in AdminOnly.
- Performance logic lives in small src/lib/perf modules; database triggers enforce approval locks and record transitions, and imports reparse stored workbooks before a user-scoped transactional RPC to protect approved definitions.
- Performance references use KPI IDs; a single database structural RPC owns draft numbering, while compatibility codes are synchronized by triggers. XML export uses DOM editing and independent XML validation to preserve template formulas and styles.
- Translation and individual formula suggestions share AI_TEXT_MODEL in src/lib/ai-model.ts so model changes have one source.
